# 112_yuv_rgb_player 实现分析

## 一、项目定位

一个**不依赖解码器**的裸像素播放器：不解析容器、不做 H.264 解码，直接把
`ffmpeg -pix_fmt xxx -f rawvideo` 导出的**无头裸帧文件**按“宽 × 高 × 像素格式”
解释成图像，喂给 SDL 显示。支持 **YUV420P / RGBA / ARGB / BGRA / RGB24** 五种格式，
双路独立播放，可分别设置宽、高、帧率。

技术栈：

| 依赖 | 用途 | 备注 |
|---|---|---|
| Qt 6 Widgets | 界面、事件循环、文件对话框 | 控件全部来自 `rgbyuvplayer.ui` |
| SDL2 | 纹理上传 + 缩放 + 上屏 | 2.32，嵌入 Qt 控件窗口 |
| FFmpeg `libavutil` / `libavcodec` | 只用 `AVFrame` / `av_frame_get_buffer` / `av_strerror` | 不做解码，只借用帧缓冲管理 |

源码规模（约 1100 行）：

| 文件 | 行数 | 职责 |
|---|---|---|
| `main.cpp` | 11 | 起 `QApplication`，显示主窗口 |
| `rgbyuvplayer.ui` | 330 | 界面布局（控件绝对定位，无 layout） |
| `rgbyuvplayer.h/.cpp` | 60 / 232 | 播放控制器：读控件、开文件、定时、线程、FPS 角标 |
| `xvideoview.h/.cpp` | 145 / 206 | **渲染抽象层**：文件读取 + AVFrame 管理 + 帧率统计 + 接口定义 |
| `xsdl.h/.cpp` | 61 / 302 | **SDL 后端**：窗口/渲染器/纹理 + 等比缩放上屏 |

## 二、四层结构

```text
┌────────────────────── UI 层（rgbyuvplayer） ───────────────────────┐
│ width1/height1/set_fps1  pix1(QComboBox)  video1(QLabel)          │
│ width2/height2/set_fps2  pix2(QComboBox)  video2(QLabel)          │
│ fps1/fps2  →  运行期被改成 video1/video2 的原生子窗口（角标）      │
│ 职责：把"用户参数"翻译成 Init(w,h,fmt)，不碰任何像素              │
└──────────────────────────────┬───────────────────────────────────┘
                               │ XVideoView* （基类指针，不认识 SDL）
┌──────────────────────────────▼───────────────────────────────────┐
│ 渲染抽象层 XVideoView（xvideoview）                                │
│  · 文件侧：OpenFile → ReadFile → AVFrame（含 linesize 语义）       │
│  · 分发侧：DrawFrame 按 format 选单平面/三平面 Draw                │
│  · 尺寸侧：Scale(w,h) 把"宿主控件尺寸"透传给后端                   │
│  · 统计侧：render_fps() 每秒结算一次                               │
│  · 工厂：Create(RenderType) → SDL / (预留 OPENGL、DIRECTX)         │
└──────────────────────────────┬───────────────────────────────────┘
┌──────────────────────────────▼───────────────────────────────────┐
│ 后端实现层 XSDL（xsdl）                                            │
│  SDL_Window + SDL_Renderer + SDL_Texture + FitRect 等比缩放        │
│  Init / Draw×2 / Present / Close / IsExit 全部加 mtx_ 保护          │
└───────────────────────────────────────────────────────────────────┘
```

设计意图：**上层只描述“要画什么、画多大”，下层决定“怎么画”**。换 OpenGL 后端
只需再写一个 `XOpenGL : public XVideoView`，UI 层一行不用改。

## 三、启动流程：从进程起来到“可以播放”

```text
main()
 └─ RgbYuvPlayer w;  w.show();
     │
     ├─ 构造函数：ui->setupUi(this)
     │   └─ QTimer::singleShot(100ms, initSDL)     ← 等窗口 show 完，label 才有真实尺寸
     │
     └─ initSDL()                                    （rgbyuvplayer.cpp:193）
         ├─ connect(this, VIEWS → View)              ← 跨线程通道，见 §6.5
         ├─ views_.push_back(XVideoView::Create())    ← 工厂造两个 XSDL
         ├─ set_win_id(ui->video1->winId())           ← ★ 把 Qt 控件的 X11 Window 交给 SDL
         ├─ last_pts_.assign(2, time_point{})         ← 每路一个上次渲染时间戳
         ├─ video1/video2->installEventFilter(this)   ← label 尺寸变化 → SyncScale()
         ├─ SyncScale()                               ← Scale(400,300)
         ├─ AttachFpsOverlay(ui->fps1, ui->video1)    ← ★ 角标变成 label 的原生子窗口
         └─ th_ = std::thread(&Main, this)            ← 启动节拍线程
```

此时还没有任何视频：纹理、AVFrame、文件句柄都是**第一次点 Open 才创建**。
这样可以“先开窗口、后选文件”，也支持中途换文件/换分辨率/换格式。

## 四、打开一个文件：`Open(i)`

```text
点击 Open1 → Open(0)                                   （rgbyuvplayer.cpp:139）
 ├─ QFileDialog 取路径（空则返回）
 ├─ views_[i]->OpenFile(path)                          （xvideoview.cpp:58）
 │   ├─ 关旧流、重置 file_size_
 │   ├─ 二进制打开
 │   └─ seekg(end) 取文件总字节数 → file_size_          ← 供 §7 的自检用
 ├─ 从控件取 w / h / fmt 字符串 → 映射成 PixFormat 枚举
 ├─ views_[i]->Init(w, h, fmt)                          （xsdl.cpp:137）
 │   ├─ InitVideo()：SDL_Init(SDL_INIT_VIDEO) 只做一次 + 设缩放质量 hint
 │   ├─ 加锁
 │   ├─ 窗口只建一次：
 │   │    有 win_id_ → SDL_CreateWindowFrom(win_id_)   嵌入 Qt label
 │   │    没有       → SDL_CreateWindow(...)            独立窗口
 │   ├─ 销毁旧 texture/renderer，重新 SDL_CreateRenderer
 │   │    ACCELERATED 失败 → 回退 SOFTWARE；并打印实际的 "SDL renderer: xxx"
 │   ├─ view_w_/view_h_ = 0                ← 强制下一帧重设 viewport
 │   └─ 按 fmt 映射出 sdl_fmt，SDL_CreateTexture(STREAMING, w, h)
 ├─ CheckFileSize(i, w, h, fmt)                        （rgbyuvplayer.cpp:67）
 │     校验 文件大小 % 单帧字节数 == 0，否则弹窗（宽高/格式填错的兜底）
 └─ SyncScale()                                        ← 再喂一次 label 尺寸
```

关键点：**窗口、渲染器、纹理是三件独立的资源**。窗口跨文件复用（避免反复
`CreateWindowFrom`），渲染器和纹理按新的 `(w,h,fmt)` 重建，所以换文件不会泄漏。

## 五、播放循环：一帧数据怎么走到屏幕上

```text
节拍线程 th_                                 UI 线程（Qt 事件循环）
────────────                                 ──────────────────────
Main():
  while (!is_exit_)
      emit ViewS();  ──── 队列连接 ────►  View()   （rgbyuvplayer.cpp:109）
      MSleep(10);                          │
                                           ├─ 读 set_fps1/2 → 帧率节流
                                           │   if (now - last_pts_[i] <= 1000/fps) 跳过
                                           │   last_pts_[i] = now
                                           ├─ ReadFile()                ← 纯文件 I/O
                                           ├─ DrawFrame(frame)
                                           ├─ render_fps() → 只在变化时 setText
                                           └─ last_pts_ 维护
```

### 5.1 `ReadFile()`：文件字节 → AVFrame

```cpp
frame_->width/height = width_/height_;   frame_->format = fmt_;
av_frame_get_buffer(frame_, /*align=*/1);      // ★ 1 = 紧排，不留对齐填充
```

- **align=1 是这里最要紧的一处**：`linesize[0] == 宽 × 每像素字节数`。
  好处一：一帧一个 `read()` 就够；好处二：交给 SDL 的 pitch 不带填充
  （原因见 §6.2）。
- 参数变化（换尺寸/换格式）时先 `av_frame_free` 再重建，帧缓冲与文件同步。
- 读取用 `ReadPlane()`（xvideoview.cpp:18）：
  - `pitch == width`（紧排）→ 一次 `read(width*height)`
  - 否则逐行 `read(width)` 跳过填充 —— **兼容外部带 stride 的缓冲区**
  - 读不满（EOF/截断）→ 返回 `nullptr`，播放循环自然停住

### 5.2 `DrawFrame()`：按 format 分流（xvideoview.cpp:171）

```cpp
switch (frame->format) {
case AV_PIX_FMT_YUV420P:                       // 平面分离：Y/U/V 各有自己的 pitch
    return Draw(Y, Ypitch, U, Upitch, V, Vpitch);
case AV_PIX_FMT_RGBA: case AV_PIX_FMT_ARGB:
case AV_PIX_FMT_BGRA: case AV_PIX_FMT_RGB24:   // 打包：单指针 + 单 pitch
    return Draw(data[0], linesize[0]);
default:
    return false;                              // 不支持的格式显式失败，别静默
}
```
顺手在这里做 FPS 统计：`count_` 累加，距离 `beg_time_` 超过 1 秒就
`render_fps_ = count_`、清零重计。

### 5.3 `Present()`：等比缩放 + 居中上屏（xsdl.cpp:90）

```text
目标区域 = Scale() 给的 label 尺寸（未给则退回视频原始尺寸）
        ↓ FitRect(dst_w, dst_h)         交叉相乘比较宽高比，整数运算无浮点误差
        ↓ 得到 {x, y, w, h}             例：1920×1080 放进 400×300 → {0, 37, 400, 225}
        ↓ SDL_RenderSetViewport({0,0,dst_w,dst_h})   尺寸变了才设，避免每帧开销
        ↓ 非铺满时 SDL_RenderClear（只有黑边需要清）
        ↓ SDL_RenderCopy(texture, NULL, &rect)       缩放交给 GPU/软件缩放器
        ↓ SDL_RenderPresent
```

一次完整的数据流（以 1920×1080 RGBA → 400×300 的 label 为例）：

```text
文件 8294400 B/帧
  → AVFrame: data[0], linesize=7680 (=1920×4, 紧排无填充)
  → SDL_UpdateTexture(texture(1920×1080, ABGR8888), data[0], 7680)
  → FitRect(400,300) = (0,37,400,225)        ← 16:9 保持，上下各 37px 黑边
  → SDL_RenderCopy(缩放到 400×225) → X11 label 窗口 → 屏幕
```

## 六、六个关键设计决策（大多是被具体 bug 逼出来的）

### 6.1 嵌入模式不用 `SDL_RenderSetLogicalSize`

SDL 的逻辑分辨率依赖“SDL 自己知道的窗口尺寸”。而在 `SDL_CreateWindowFrom`
嵌入模式下，没有 SDL 事件泵去处理 `ConfigureNotify`，SDL 缓存的尺寸永远是创建时
的值 —— 宿主 label 一变，缩放就失效。

所以改成分工明确：**Qt 侧把 label 真实尺寸告诉后端**（`Scale()` + `eventFilter`），
**后端自己算目标矩形 + 重设 viewport**。顺带得到两个好处：等比不变形、
黑边可控（想改成“裁剪铺满”只改 `FitRect`）。

### 6.2 `linesize` 一定要紧排

`av_frame_get_buffer(frame, 0)` 会**把宽度按像素对齐**（对齐到 16/32/64 像素）再乘
每像素字节数，所以 RGB24 的 linesize 恒为 `3 × 对齐后宽度`：

| 宽 | 紧排 w×3 | align=0 的 linesize | 填充字节 |
|---|---|---|---|
| 400 | 1200 | 1248（宽按 16 对齐 → 416） | 48 |
| 1280 | 3840 | 3840 | 0 |
| 1920 | 5760 | 5760 | 0 |
| 683 | 2049 | 2064（宽按 16 对齐 → 688） | 15 |

实测 `w = 1..300` 时 `linesize % 3 != 0` 的数量为 **0** —— 也就是说，
“SDL 用 `pitch / 每像素字节数` 做整数除法导致错位”这个坑，**从
`av_frame_get_buffer` 这条来源走不到**。真正让 RGB24 花屏的是另一处：
`Init()` 里 `case RGB24:` 漏写 `break`，掉进 `YUV420P` 分支，纹理被建成 IYUV。

但填充本身仍有代价，这也是为什么这里改成了 `align = 1`：

1. **正确性**：按 `linesize × 高度` 直接从文件读会连填充字节一起读走，
   后续每一帧整体错位（本项目最初的 bug 之一）。填充为零时才能整帧一次读完。
2. **可移植性**：`linesize` 不是每像素字节数整数倍的情况确实存在 ——
   `sws_scale` 输出、自己按字节对齐算的缓冲区、外部解码器给的帧都是例子。
   一旦碰上，SDL 的整数除法就会把画面切成斜的。紧排后 pitch 恒等于
   `宽 × 每像素字节数`，这类问题一次性关掉。
3. **性能**：`pitch == width` 让 `ReadPlane()` 走单次 `read()`，
   一帧一个 syscall，而不是逐行 1080 次。

| 获取方式 | RGB24 400 宽的 linesize | 说明 |
|---|---|---|
| `av_frame_get_buffer(f, 0)` | 1248 | 宽度像素对齐，逐行读必须跳填充 |
| `av_frame_get_buffer(f, 1)` | 1200 | **本项目采用**：零填充，整帧单次读 |
| `av_image_fill_linesizes(..., 32)` | 1216 | 按**字节**对齐 → 1216 不是 3 的倍数，喂给 SDL GL 就会斜切 |

### 6.3 两个 `Draw` 重载，对应两类内存布局

| 布局 | 代表格式 | 接口 | SDL 调用 |
|---|---|---|---|
| 打包（packed） | RGBA/ARGB/BGRA/RGB24 | `Draw(data, linesize)` | `SDL_UpdateTexture` |
| 平面（planar） | YUV420P | `Draw(y,yp,u,up,v,vp)` | `SDL_UpdateYUVTexture` |

FFmpeg 解码出来的 YUV 天然是平面分离且每平面 pitch 不同，三平面重载就是为它准备的；
打包格式则走单指针 + 单 pitch。

### 6.4 枚举值刻意与 `AV_PIX_FMT_*` 数值一致

```cpp
enum PixFormat { YUV420P = 0, RGBA = 26, ARGB = 25, BGRA = 28, RGB24 = 2 };
```

于是 `frame_->format = fmt_` 可以直传，`DrawFrame` 能直接用 `AV_PIX_FMT_*` 做 case。
代价是隐式耦合 —— 建议加 `static_assert(static_cast<int>(RGBA) == AV_PIX_FMT_RGBA, ...)`。

SDL 那边要注意“别名格式”与“内存字节序”的对应关系（小端）：

| AV 格式 | 内存字节序 | 正确 SDL 格式 | 等价的显式格式 |
|---|---|---|---|
| `AV_PIX_FMT_RGBA` | R G B A | `SDL_PIXELFORMAT_RGBA32` | `ABGR8888` |
| `AV_PIX_FMT_ARGB` | A R G B | `SDL_PIXELFORMAT_ARGB32` | `BGRA8888` |
| `AV_PIX_FMT_BGRA` | B G R A | `SDL_PIXELFORMAT_BGRA32` | `ARGB8888` |
| `AV_PIX_FMT_RGB24` | R G B | `SDL_PIXELFORMAT_RGB24` | — |
| `AV_PIX_FMT_YUV420P` | Y/U/V 三平面 | `SDL_PIXELFORMAT_IYUV` | — |

写 `SDL_PIXELFORMAT_RGBA8888`（而不是 `RGBA32`）会得到 A B G R 的内存序 →
**红蓝互换**。这是最容易踩的一脚。

### 6.5 线程模型：只有一条跨线程通道

```text
th_  ──emit ViewS()──►  Qt 事件队列  ──►  View() 在 UI 线程执行
```

- `View()` 是槽函数，`emit` 发生在工作线程，连接类型是**队列连接**，
  所以槽体天然跑在 UI 线程 —— Qt 控件操作安全。
- 退出标志 `is_exit_` 用 `std::atomic<bool>`（普通 bool 跨线程读写是 UB）。
- `views_`、`last_pts_`、`ui` 都只在 UI 线程被访问；`XSDL` 内部的
  `width_/scale_w_/texture_` 由 `mtx_` 保护（`Scale()` 也会加锁）。

### 6.6 FPS 角标必须是“原生子窗口”

`video1/video2` 的 X11 窗口是被 SDL **直接绘制**的，绕过了 Qt 的绘制引擎。
普通子控件（alien widget）画在父窗口的 backing store 上，SDL 每帧清屏重画就把它盖掉。
用 `WA_NativeWindow` 让 QLabel 拥有自己的 X 子窗口后，X11 中子窗口永远叠在
父窗口内容之上，于是能稳定贴在画面左上角（`AttachFpsOverlay()`）：

```cpp
fps->setParent(video);
fps->setAttribute(Qt::WA_NativeWindow);            // 关键
fps->setAttribute(Qt::WA_TranslucentBackground);   // ARGB，半透明底
fps->setAttribute(Qt::WA_TransparentForMouseEvents);
```

同时 `render_fps()` 一秒才变一次，所以 `setText` 前要比较文本，避免 25Hz 无谓重绘。

## 七、怎么再加一种像素格式（扩展点清单）

以加 **`BGR24`** 这样的打包格式为例，一共 **5 处**：

| # | 位置 | 改什么 |
|---|---|---|
| 1 | `xvideoview.h` `enum PixFormat` | 加 `BGR24 = 3`（**数值必须等于 `AV_PIX_FMT_BGR24`**） |
| 2 | `xvideoview.cpp` `BytesPerPixel()` | `case AV_PIX_FMT_BGR24: return 3;` |
| 3 | `xvideoview.cpp` `FrameBytes()` | 归入 `w*h*3` 分支（用于文件大小自检） |
| 4 | `xvideoview.cpp` `DrawFrame()` | 在打包格式的 case 列表里加 `AV_PIX_FMT_BGR24` |
| 5 | `xsdl.cpp` `Init()` | `case BGR24: sdl_fmt = SDL_PIXELFORMAT_BGR24; break;` |

再补两处**界面/映射**：

| # | 位置 | 改什么 |
|---|---|---|
| 6 | `rgbyuvplayer.ui` | `pix1`/`pix2` 下拉框加一项 `BGR24` |
| 7 | `rgbyuvplayer.cpp` `Open()` | 字符串 → 枚举的分支加一条（或按 §7.2 改成 itemData） |

**平面格式**（如 `YUV422P`）还要多两点：`DrawFrame` 里调用三平面 `Draw`，
并在 `ReadFile` 的读取分支里按格式算各平面宽高。

**半平面格式**（如 `NV12`）目前 SDL 后端没有对应路径，需要新增
`SDL_UpdateNVTexture` 分支 —— 这也是当前抽象层的一个边界。

### 7.1 推荐重构：把 5 处 switch 合成一张表

现在的改动分散在 5 个 `switch` 里，漏一处就是“能跑但画面错”（RGB24 掉进
YUV 分支就是这么来的）。可以集中成一张 `constexpr` 表：

```cpp
struct PixFmtInfo {
  XVideoView::PixFormat fmt;
  AVPixelFormat          av;        // 与 fmt 数值一致，用于 static_assert
  Uint32                 sdl;       // SDL 纹理格式
  const char            *name;      // 界面显示名
  int                    planes;    // 1 = packed, 3 = planar
  int                    bpp;       // packed 用；planar 填 0
};

static constexpr PixFmtInfo kFormats[] = {
  {YUV420P, AV_PIX_FMT_YUV420P, SDL_PIXELFORMAT_IYUV,   "YUV420P", 3, 0},
  {RGBA,    AV_PIX_FMT_RGBA,    SDL_PIXELFORMAT_RGBA32, "RGBA",    1, 4},
  {ARGB,    AV_PIX_FMT_ARGB,    SDL_PIXELFORMAT_ARGB32, "ARGB",    1, 4},
  {BGRA,    AV_PIX_FMT_BGRA,    SDL_PIXELFORMAT_BGRA32, "BGRA",    1, 4},
  {RGB24,   AV_PIX_FMT_RGB24,   SDL_PIXELFORMAT_RGB24,  "RGB24",   1, 3},
};
```

配套收益：
- 新格式只加一行；
- 下拉框可以由 `kFormats` 自动填充（`addItem(name, QVariant::fromValue(int(fmt)))`），
  `Open()` 里那串 `if (pix == "RGBA") ...` 全部消失；
- `FrameBytes()` / `BytesPerPixel()` / 纹理格式映射全都变成查表。

### 7.2 文件大小自检（已经内置）

裸像素文件没有头信息，宽高填错时唯一的外部线索就是**文件大小**：

```text
file=8294400 bytes, frame=8294400 bytes, frames=1
```

`file_size % FrameBytes(w,h,fmt) != 0` 说明参数和文件对不上，`CheckFileSize()`
会弹窗提示。排查“画面斜切/变形”时先看这一行：**帧数必须是整数**。

## 八、故障排查对照表

| 现象 | 最可能原因 | 定位手段 |
|---|---|---|
| 全黑/什么都没画 | `SDL_Init` 失败（Wayland 原生下 `CreateWindowFrom` 不可用）、`Init` 返回 false | 日志是否有 `wayland,x11,windows not available`；`SDL_VIDEODRIVER=x11` 对比 |
| 画面斜切/逐行错位 | ①宽高与文件实际尺寸不符（最常见）②pitch 不是每像素字节数整数倍 | 看 `frames=` 是否为整数；确认 `av_frame_get_buffer(..., 1)` |
| 红蓝互换 | 用了 `SDL_PIXELFORMAT_RGBA8888` 而不是 `RGBA32` | 对照 §6.4 表 |
| RGB24 花屏（颜色像灰阶/错乱） | 纹理被建成 IYUV（`Init()` 里 `case` 漏 `break`） | 对照 `Init()` 的 sdl_fmt 映射表 |
| 视频被裁掉一角、不是等比 | 没人调 `Scale()`，`dst` 退回视频原始尺寸 | `Present()` 里打印 `dst_w/dst_h` |
| 画面不动但程序没崩 | `ReadFile()` 一直返回 `nullptr`（EOF / 参数错） | 打印 `file_size`、`frame_bytes` |
| FPS 一直是 0 | 没进 `View()` 或帧率设为 0 | 检查 `set_fps1/2` 是否 > 0 |
| 有画面但角标被盖住 | 角标没用原生子窗口 | 检查 `WA_NativeWindow` |

## 九、后续可优化

1. **UI 用 layout**：现在控件全是绝对坐标，窗口拉大 label 不变大，等比缩放没有发挥空间。
2. **下拉框用 itemData**：`addItem(name, fmt)` + `currentData().toInt()`，替代字符串比较。
3. **I/O 挪到工作线程**：`ReadFile()` 目前在 UI 线程（槽函数在 GUI 线程执行），
   大文件会有读盘抖动；可改成双缓冲 + 工作线程读、UI 线程画。
4. **节拍改成 deadline 累加**：现在是 `last_pts = now` + 10ms 轮询，会有累计漂移。
5. **默认 Release 构建**：`CMakeLists.txt` 在没指定时默认 `Debug`（-O0）。
6. **`Create()` 加判空**：`OPENGL` 分支返回 `nullptr`，调用方 `push_back(nullptr)` 会崩。
7. **清理死代码**：`ReverseRow()`、`FixLinesize()`、空 `moveEvent()`、`IsExit()` 未被调用。
